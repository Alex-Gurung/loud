### 1. [major] The comparison gate passes with missing comparison steps

- where: `loud/compare.py:49`
- evidence: The code compares only `set(a) & set(b)` and requires merely one common step. I supplied three steps in A, one matching step in B, and `first: 50`; the result reported `steps_compared: 1`, `complete: true`, and check `pass`. Missing log entries therefore weaken the verification gate silently.
- fix: Require the requested number of comparison steps. For sparse published logs, require every expected published step within the comparison range to exist in the port’s log. Reject duplicate step records rather than silently overwriting them.

### 2. [major] “Untimed” trajectory means leak into reported training time

- where: `loud/train.py:110`
- evidence: `TrajectoryMeans.observe()` queues CUDA clones and `lerp_` operations (`loud/checkpoints.py:79–85`). The loop then subtracts only the host duration of that work at line 117, without waiting for its GPU completion. When no scoring or checkpoint forces synchronization, the next update’s `loss.item()` waits for the outstanding mean operations, charging their remaining duration to training. All E1 cells enable means, so reported training times include a variable amount of supposedly excluded work. This follows from the source’s stream ordering; the magnitude was not measured because CUDA is unavailable.
- fix: Synchronize before ending a pause that queued GPU work, or use CUDA events to measure and exclude that work accurately.

### 3. [major] Collection silently omits failed and crashed attempts

- where: `loud/collect.py:29`
- evidence: Collection explicitly skips attempt and direct-run directories. Workers leave failures in `s<seed>.attempt<k>/`; only successful attempts become `s<seed>/`. I created a crashed `s0.attempt1/` containing `config.json`; `collect.runs()` returned `([], [])`. Thus the Round 1 claim that crashed runs are listed remains false under the new directory layout.
- fix: Report unresolved failed/crashed attempt directories separately, using queue state to distinguish active attempts and superseded retries. Keep them excluded from averages.

### 4. [minor] Submission accepts options that fail after initialization and warmup

- where: `loud/options.py:94`
- evidence: `specs_from_config()` accepted `args: {stop_after: -1, lr_mult: -5}`. A CPU reproduction through the shared loop with `stop_after: -1` performed warmup, skipped every training update, then raised `UnboundLocalError` for `loss` at `loud/train.py:122`. Validation checks batch and held-out sizes but leaves stop counts, monitoring intervals, and learning-rate multipliers unchecked.
- fix: Validate stop counts and intervals as nonnegative integers, boolean options as booleans, and `lr_mult` as a finite positive number before submission.

### 5. [minor] The whole-batch gradient test compares against a mutable alias

- where: `tests/method_checks.py:60`
- evidence: After `trainer.gradient(batch)`, float32 parameter gradients alias the trainer’s accumulators. `direct(batch)` does not clear those gradients before backward, and its returned `p.grad.float()` keeps the alias. The next `trainer.gradient()` zeroes and rewrites that same storage. A minimal reproduction showed the supposed expected gradient change from `34.0` to `17.0` during the call being tested, then compare equal to the actual gradient. This assertion cannot independently validate float32 gradients.
- fix: Clear gradients before each direct backward and clone every expected gradient before invoking the implementation under test.
