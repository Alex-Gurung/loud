The queue has retry and crash-recovery defects that can corrupt run artifacts or execute a job twice. The collector also averages results it claims to exclude. All 12 CPU tests pass, but they do not cover these failures; CUDA performance was not measured.

### 1. [blocker] Expired attempts can overwrite a retry’s artifacts
- where: `loud/jobqueue.py:158`, `loud/jobqueue.py:185`, `loud/worker.py:139`
- evidence: Recovery renames the existing run directory and reuses its original path for the retry. The old child retains that absolute output path and performs no lease checks; only its parent checks periodically. A scratch reproduction claimed attempt 2, created its checkpoint, then demonstrated that a late write through attempt 1’s original path overwrote it. Ownership also checks only worker identity: after reclaiming with the same worker ID, attempt 1 successfully called `finish()` for attempt 2.
- fix: Give each attempt a distinct output directory and lease token. Require the token for heartbeats and completion, and publish the accepted attempt only after verifying ownership.

### 2. [major] Queue transitions can leave a job claimable twice after a crash
- where: `loud/jobqueue.py:71`
- evidence: `_move()` writes the destination record before unlinking the source. Injecting an interruption at the unlink during `claim()` left both `queued/x.json` and `running/x.json`. A subsequent worker successfully claimed `x` again despite the existing running record. `flock` does not repair this state after process death.
- fix: Update the source record under the lock, then atomically rename it to the destination. Add a fault-injection test for interrupted transitions.

### 3. [major] Failed-check runs enter the reported averages
- where: `loud/collect.py:67`
- evidence: The module promises that “incomplete or failed-check runs are listed apart,” but the inclusion condition checks only completeness and validation loss. Calling `table()` with a passing loss of `3.0` and a failed-check loss of `9.0` produced `n=2`, mean `6.0`; the failure merely added a flag.
- fix: Exclude rows whose check is `fail` from aggregation and list them alongside incomplete or unscored runs.
