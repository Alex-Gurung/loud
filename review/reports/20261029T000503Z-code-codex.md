### 1. [major] `direction_stats` mixes token-summed gradients with token-mean optimizer state
- where: `loud/diagnostics.py:263`
- evidence: The diagnostic differentiates `loss_reduction='sum'`, then divides only by the number of sequences at line 269. Training differentiates the default token-mean loss, so the diagnostic’s gradient is 2,048 times larger for benchmark sequences. Line 280 mixes that gradient with saved, token-mean fast/slow rails. A numerical reproduction changed the leading singular direction from `diag(0,1)` to the orthogonal `diag(1,0)` solely through this scaling. The reconstruction also skips the fast/slow rail updates that the optimizer performs before forming its pending update. The updated test checks `directions_from == 'pending update'`, but never compares the reconstructed tensor with the optimizer’s actual pre-polar tensor.
- fix: Normalize gradients by valid-token count, apply the optimizer’s rail recurrence before constructing the pending update, and test against an actual captured pre-polar tensor.

### 2. [minor] E8 replaces the compiled batched optimizer update with eager tensor operations
- where: `loud/anvil.py:77`
- evidence: PR #40’s `anvil_update` has `@torch.compile(dynamic=False)`. Its replacement, `shaped_update`, has no compilation wrapper and directly invokes the undecorated `polar_batch`, followed by eager energy, gain, norm and decay operations. Thus enabling E8 removes fusion from the existing optimizer arithmetic in addition to adding damping. `batched_anvil_hook` verifies numerical equality with Dynamo disabled, so it cannot catch this regression. The GPU slowdown is unverified.
- fix: Preserve compilation around the stable tensor portions, separating the refresh/SVD hook where necessary. Verify compilation and benchmark ordinary, non-refresh updates against the baseline.
