### 1. [major] Adding default `gpus: 1` breaks existing job identity
- where: `loud/run.py:101`
- evidence: The hash now always includes `gpus`, changing every existing single-GPU config’s hash. For unchanged `configs/e1/bp_b8.yaml`, the old hash begins `ccaa15da` and the new hash begins `2468f81a`. The live queued `e1.bp_b8.s0` record matches the old hash. Calling `JobQueue._decide` rejects this unchanged config in queued, running, and done states with “different config”; routine resubmission can no longer refresh queued code without `--rerun`.
- fix: Preserve the old hash payload when `gpus` defaults to 1, and include the field for larger counts. Add a regression test using a legacy queue record.

### 2. [major] Worker GPU discovery ignores CUDA device visibility
- where: `loud/worker.py:62`
- evidence: `gpu_info()` counts `nvidia-smi` rows, which do not follow `CUDA_VISIBLE_DEVICES`. With `CUDA_VISIBLE_DEVICES=0` and a mocked eight-row host query, it returns `('H100', 8)`. That count feeds the new exact-count filter in `claim`: a worker restricted to one device skips single-GPU jobs and can claim an eight-GPU job whose ranks cannot access eight devices.
- fix: Discover the CUDA-visible count and first visible device using the job interpreter, retaining the intentional CPU fallback. Test masked device visibility.
