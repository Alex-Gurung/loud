# Code review, round 7 (commit a387d8d): H8, its experiments and E8's H8 setting

**Verdict.** The new H8 core (cut graph, synthesis's block-local credit routing, the schemes, Replay, ShapedBatchedAnvil) is
careful, and it matches PR #40 and the Cut port where I checked. I found no blocker. Two quiet differences from the
code H8 is meant to stand in for will bite the results. E16's n-gram tables train at Adam ×1, the head's rate, because
PR #40's `make_optimizer` has no rule for them. H8's E7 prior also corrects S0, where the Cut chain's E7, the flag that
confirms H8's winners, has no guess. The rest is minor: diagnostics inside the timed update, a gate prefix that no
longer narrows the sites, a dead `row_budget` option, and validation that differs between H8 and the chain.

All 110 tests pass (`pytest -q -p no:cacheprovider tests`, about 55 minutes on this heavily loaded pod). None of them
would catch findings 1 or 2: no check reads the E16 optimizer's groups or compares H8's prior with the chain's at S0.

### 1. [major] E16's n-gram tables (402M of the 614M parameters) train at Adam ×1, the head's rate, not as embedding tables
- where: `loud/arch.py:1-5` ("so both train under one recipe"), `loud/h8.py:614`, `loud/proxy.py:56`; the rule they
  inherit is `external/noise/archive/10M/train/val/run.py:2191`
  (`scale = 300 if ('wte' in name or 'value_embeds' in name) else 30 if 'lambdas' in name else 1`).
- evidence: I built the track-3 model with `arch.make_model` and gave it to PR #40's `make_optimizer`. The Adam groups
  came out as `x300: wte, value_embeds.*` and `x1: lm_head, ngram_embeds.{2,3,s}, ngram_proj.*, ve_gate`. Track-3
  record #5's own optimizer (`external/noise/train/arch/run.py:2468-2471`, `emb_scale 750`, `ngram_scale 0 → emb_scale`)
  trains the tables at ×750, 750 times faster. `init_weights` stores the tables in bf16 on CUDA, with entries ~N(0, 1).
  So a step of lr = 0.0021 changes only 68% of the entries, and at the warmdown's 30% (0.00063) only 20% (round to
  nearest, measured on 10⁶ N(0,1) bf16 values). Each table row is also hit about 10 times per epoch (10M tokens, 2²⁰
  rows). I simulated that: PR #40's AdamW (betas 0.5/0.98) on a bf16 N(0,1) table, every row hit 10 times in 1,212
  updates, under the record's warmdown. The rows moved by an RMS of 0.027 at ×1 (11% of the entries never changed),
  against 10 at ×300 and 25 at ×750. In both E16 trainers the tables therefore stay near their random init. That makes the arm a
  fixed-random-feature variant of the design, so it does not test the design behind the leaderboard's 3.211 vs 3.338.
  Neither the README nor the E16 configs mention it.
- fix: in `arch.py`, wrap `make_optimizer` (used by both `H8.make_optimizer` and `Reference`) so that
  `ngram_embeds.*` joins the embedding group (×300, PR #40's embedding scale, or the record's ×750). Or state the
  choice in `configs/e16/*` and the README.

### 2. [major] H8's E7 prior corrects S0 with a guess; the Cut chain's E7 (the flag that confirms H8's winners) has none there
- where: `loud/h8.py:318-323` (`identity_guess` builds `guess[0]` through x0's skips and the RMS norm) and
  `loud/h8.py:361-362` (`p = guess[k]` for every k, S0 included); compare `loud/cut.py:186-193` (`guesses()` covers mid
  sites 0..L-1 only), `loud/cut.py:283-294` (`guesses.get(site)` is None for the embedding) and the cut.py docstring:
  "The embedding site S0 has no guess ... and keeps the plain estimate".
- evidence: with `prior: identity`, H8 reads S0 as `p0 + (1/m) Σ v·(g0 − p0) v`, while the chain reads it as the plain
  `(1/m) Σ (v·g0) v`. S0's credit is all of wte's gradient, so `e7.prior_m64`/`m128` in H8 differ from the chain's E7
  in the variance of one parameter group. The win or loss that H8 reports is not the one `rows`/`prior` will reproduce
  on the chain. The H8 docs (`Scheme` docstring, README "Schemes") say nothing about S0.
- fix: pick one rule for both. To keep H8 the chain's emulator, use `p = guess[k] if self.prior == 'identity' and
  k > 0 else None` in `Scheme.__call__` (the S0 guess can stay in `credit_dump`). Otherwise add the S0 guess to
  `Cut.guesses`. Name the rule in both READMEs.

### 3. [minor] H8's per-update diagnostics run inside the clock; E6's per-update cosine adds about 48% to every synthesis gradient
- where: `loud/h8.py:563-568` (`compare`: a second `block_local` pass over the exact credits), `loud/h8.py:702-703`
  (`stable_ranks`: 48 spectral norms and 48 `.item()` syncs), `loud/h8.py:690-692` (E14's `gradient_cosine`, two extra
  backward calls). These are all inside `trainer.update`, which `loud/train.py:115-119` times. The train.py docstring
  says "the clock covers the updates only (diagnostics, held-out scoring and checkpoints are paused out)".
- evidence: `configs/e6/*.yaml` set `compare_every: 1` and `rank_every: 10`. I timed `synthesis_gradients` on CPU
  (7m preset, B 4, T 256, 12 interleaved runs, process time, trimmed mean): 1.67 s without the compare and 2.48 s with
  it (+48%). E6's 18 runs (about 3 GPU-hours by the README's estimate) therefore cost roughly an extra hour. Their
  `step_seconds` and `train_seconds` cannot be compared with `e1.h8_synth`'s.
- fix: H8 times are not results, so the cost is the plan's (it asks for the cosine per update). The fix is to keep the
  diagnostics out of the clock. Time those sections in `update` (sync, then perf_counter) and return their seconds in
  a field that `train.py` adds to `pause_total`. Or log every 10 updates and say so in the configs.

### 4. [minor] E7's gate prefix `S` selects all nine sites: round 6's "eight mid sites" fix is lost with the S0..S8 renaming
- where: `configs/e7/precondition.yaml` (`[..., variance_ratio, S]`), `loud/gate.py:24` (`site.startswith(prefix)`);
  ledger round 6, 20261029T010000Z-round6-claude.md #4.
- evidence: a fake `credit_dump.json` with variance_ratio 5.0 at S0 and 0.4 elsewhere, through `gate.run_task`, gives
  `c50_sites = ['S0', ..., 'S8']`. The median includes S0. The gate docstring's example still uses `mid`.
- fix: let a value list its sites (or take a regex), and pass S1..S8. If finding 2 keeps the S0 guess, drop the
  prefix and say so.

### 5. [minor] E13 runs the n-gram model on the CPU at every update, synchronously, inside the clock, though its losses do not depend on the run
- where: `loud/h8.py:657-662` (`batch.cpu()`, `NGram.losses`, `NGram.insert` every update), `loud/ngram.py:57-60,85-98`
  (one Python `dict.get` per unique key, 12 lookups per batch; one Python loop per unique n-gram).
- evidence: the losses are a function of the fixed data order alone (`randperm(seed 1)` for every seed), so all 9 E13
  runs and both tiers diagnostics compute the same table again. Measured on this pod: 0.71 s per batch of 4 after
  50 batches. That figure is inflated, because a bare `dict.get` costs 3.3 µs here against ~0.05–0.1 µs on an idle
  core. On a GPU node I estimate 20–50 ms per update, or 0.5–1 min of idle GPU per E13 run (unverified there). The
  tables also keep one Python dict entry per distinct n-gram and history of the 10M-token stream, at every
  order.
- fix: compute the epoch's n-gram losses once (score then insert, in the run's order) into a cached
  `[updates, B, T]` file keyed by the range and held-out count, and index it in `update`.

### 7. [minor] `h8_options` accepts two flag settings that the proxy and the chain reject for the same code

  for PR #40's BatchedAnvil.
- evidence: `h8_options(dict(prior='identity'))` returns rows None, prior identity. `Scheme.read` then returns

- fix: apply the `cut_options` prior check in `h8_options`, and either reject `checkpoint_optimizer` there too or
  check the BatchedAnvil save path and allow it in all three.

## Checked and fine
- `cut_forward` and `synthesis_gradients`' routing, derived by hand: attention i from S(i+1), MLP i from
  λ_r[i+1]·S(i+2), the last MLP from the top stream, wte from S0. The `capture_linears`/`autograd.grad` subgraphs stop
  at each sublayer. `identity_guess`'s coefficients (above[i+1]; x0: above[0] + Σ λ₀[i]·above[i+1]).
- `Scheme`: unbiasedness under the column signs. `time` uses `step % K` and `token` uses block t mod K, the same rows
  as `cut.py`'s `window_start` and `row_index`. E13's `read_tiers` is exact on the high tier and unbiased on the low.
- `ShapedBatchedAnvil` against PR #40's `BatchedAnvil.step`/`anvil_update` line by line: tensor scalars, the tall-stack
  layout, decay and ratio. The Boost→Cut handoff into it works through `stacked_state`'s gather.
- SNRScaling's r is scale-free, so H8's per-sequence contributions (G_bᵀX_b of the batch-mean loss) and the proxy's
  per-sequence mean-loss gradients give the same r. `sequence_gradients` memory at batch 8 is about 0.8 GB float32 for
  the 38M model.
- E10 agree's vote counts are exact under TF32: ±1/0 inputs, fp32 accumulation, 8,192 tokens.
- Replay: site-0 path, held keys/values/gates, runway reach = |h|. E11's clean loss comes from the same replay.
- NGram: Witten–Bell recursion, 12-bit packing (48 bits at order 4), causal score-then-insert. `copies`.
- latent.py: NextLat loss and EOT mask, the E15 predictor count (2L − 1), the float32 EMA teacher, the aux Adam on
  ANVIL's schedule fraction, aux modules stepped only while they act.
- Options: H8's one-change rule and the E8/E14/E15/E16 constraints. `loud.submit configs configs/followups --dry-run`
  validates all 201 jobs.
- `queue_order` (priority, seed, submitted_ts, id) and its test. score.py's `model_file` reaches the pinned
  `utils/eval.py`, which supports it. The scorer guard (track3 preset and default rows only) is tested.
- Diagnostics: the ridge `mean(S²)` equals mean diag(AᵀA). snr_tool's sequence wrap and its `.optim.pt` momentum.
  synth_vs_real's basis/credit capture order. h8_validation's per-parameter cosines (CPU: synthesis ≥ 0.9961 at c_q,
  Boost ≥ 0.9966, matching the README).
