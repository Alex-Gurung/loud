### 4. [minor] A SIGTERM release uses up an attempt: three pod deletions fail the job and block its dependents
- where: `loud/jobqueue.py:169-177,237-240`, `README.md:100-101`
- evidence: `release` goes through `_requeue_or_fail`, which fails the job once `attempts >= max_attempts`. Claiming and releasing three times (`scratch/code/bin/release.py`, real `MAX_ATTEMPTS`) gives `failed | released: worker received SIGTERM on the last attempt`, and the dependent shows `('blocked', 'x failed')`. Preemption or restarting workers is not the job's fault, and the README describes SIGTERM as handing the job back. Related: if SIGTERM lands during `claim()`, `execute` still starts the child, kills it and releases (one more attempt gone).
- fix: count only lease expiries (or failures) toward `MAX_ATTEMPTS`, and check `self.stopping` before `Popen`.

### 10. [minor, unverified on GPU] Identity update: a host sync per sequence and seven idle estimators' hooks put each sequence's forward launch on the critical path
- where: `loud/identity.py:79-84,98`
- evidence:
  - **Hooks.** Each of the 8 `Capture`s hooks 58 Linear/Embedding modules plus 8 blocks, so every forward runs about 460 idle hooks. On this loaded CPU (38m model, 2 tokens, median of 6 runs) 8 estimators cost 4.5 ms more per forward than 1 (`scratch/code/bin/hooks2.py`, about 10 µs per hook). An idle pod should be nearer 1 µs.
  - **Sync.** `clean_loss[y != -1]` is boolean indexing, which syncs once per sequence. PR #26's `estimate()` has no sync of its own. So the CPU cannot launch sequence r+1's (launch-bound) forward while the GPU runs sequence r's probe.
  - **Estimate.** At about 77 ms per sequence (PR #26: 46.96 s / 610 updates per GPU), the exposed time is about 4–40 ms per update, roughly 1–6%.
  - The per-sequence flat `cat` costs about 1 GB of memory traffic per update (about 0.3 ms per sequence), which is negligible.
- fix: compute the loss without a sync, e.g. `(clean_loss * (y != -1)).sum() / valid`. Register hooks only for the estimator being measured (close the others' hooks and re-add them in `measure`). Measure `step_seconds` before and after.
