The toolkit needs changes before benchmark-scale use: an accepted batch size produces undefined noise estimates, and both derivative tools perform avoidable GPU work. All 31 tests and the standalone diagnostic check pass, but they miss these cases. GPU allocation shapes were verified using meta tensors; CUDA runtime and peak memory remain unmeasured.

### 1. [major] A one-sequence batch produces NaN noise estimates and reports completion
- where: `loud/options.py:210`, `loud/diagnostics.py:229`
- evidence: `diagnose_options` accepts `batch: 1`, but `direction_stats` uses `.var()` with its default sample-variance correction. Running the actual tool on a one-sequence tiny model returned `noise: nan` for every matrix. `run_task` serializes these values and reports `complete=True` at line 302. The existing check uses two sequences.
- fix: Require `batch >= 2` for `direction_stats`, including validation at the toolkit entry point. Add a singleton-batch rejection test.

### 2. [major] Token chunking leaves a 10 GiB reverse-mode allocation inside `token_map_svd`
- where: `loud/diagnostics.py:181`
- evidence: `jacrev(to_sites)` differentiates all nine sites and 512 output channels simultaneously; only the outer token dimension is chunked. Tracing the actual method with benchmark-shaped meta tensors showed an `aten.new_zeros` allocation of `[128, 4608, 4608]`, **10.125 GiB**, and MLP backward tensors of `[128, 4608, 2048]`, **4.5 GiB each**. The returned Jacobian itself is another **1.125 GiB**. The tiny CPU check does not exercise this scale.
- fix: Bound the reverse-mode dimension with `jacrev(..., chunk_size=...)` as well as the token dimension. Alternatively, use forward-mode differentiation, since the input has 512 dimensions versus 4,608 outputs. Omit the known embedding identity map from differentiation.

### 3. [major] Curvature probes compute and clone every block gradient to consume one
- where: `loud/diagnostics.py:205`, `loud/diagnostics.py:222`
- evidence: `gradients(batch)` runs unrestricted `.backward()` and clones all 52 block matrices. Each curvature call immediately selects only `[n]`. Counting the benchmark model gives 800 directions: eight initial backwards plus 1,600 batch backwards, or 12,808 sequence-equivalents at the default batch size. Each curvature backward clones 100,667,392 bytes of block gradients—about **150 GiB of copies** across the tool—while discarding every matrix except the perturbed one. Unrestricted backward also computes parameter gradients that these calls never use.
- fix: Keep the full-gradient helper for the initial per-sequence measurements. For curvature, request only the perturbed parameter with `torch.autograd.grad(loss, params[n])`, avoiding unrelated gradient computation and cloning.
