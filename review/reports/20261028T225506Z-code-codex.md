### 1. [blocker] E8 accepts batch size one and completes with invalid weights
- where: `loud/curvature.py:76`, `loud/options.py:250`
- evidence: `proxy_options` accepts `batch=1, per_sequence_grads=True, curvature_damping=1.0`. The noise calculation uses `projections.var(0)`, whose default sample variance is NaN for one sequence. A two-update CPU reproduction produced non-finite weights after update 2 without raising. An end-to-end three-update run then returned `complete: True`, `train_loss_last: nan`, and `heldout_loss: nan`.
- fix: Reject `batch < 2` when curvature damping is enabled. Add a regression test for this option combination.

### 2. [major] Cut crashes when each virtual rank receives one probe row
- where: `loud/cut.py:226`, `loud/options.py:315`
- evidence: Options permit `rows == split`, giving `P=1`. The code appends four scalar moves, but `torch.full_like(scale[:, :2], ...)` contributes only one scale per sign because `scale` has one column. Moves therefore have five columns while scales have three. Running the first Cut update with `preset='2m', batch=1, virtual_gpus=1, rows=1` reproduced: `RuntimeError: The size of tensor a (5) must match the size of tensor b (3)`.
- fix: Allocate two scalar scales per sign explicitly, independently of `P`. Test `rows == split`, including multiple virtual ranks.

### 3. [minor] E9 forces a GPU synchronization for every micro-batch
- where: `loud/fisher.py:62`
- evidence: `self.tokens += int((targets != -1).sum())` converts a CUDA scalar to a Python integer after each Fisher backward. With batch four and micro-batch one, this adds four host-device waits per update before the training backward proceeds. GPU timing was unavailable.
- fix: Accumulate the count as a device tensor and use it directly in `before_step`, avoiding Python scalar conversion.
