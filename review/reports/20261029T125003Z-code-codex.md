### 1. [major] E13’s diagnostic cannot serialize its result
- where: `loud/diagnostics.py:365`
- evidence: `ngram.tiers_tool()` returns `(summary, tensors)`, but this line assigns that entire tuple to `summary` and sets `tensors = {}`. Line 370 then attempts to JSON-serialize the tensor payload. Both a direct call using the real `tiers()` result and an isolated `run_task()` reproduction raised `TypeError: Object of type Tensor is not JSON serializable`. Both configured E13 diagnostics fail, blocking their dependent gates and experiments. Existing tests exercise the helper without exercising this task entry point.
- fix: Unpack the return value directly: `summary, tensors = ngram.tiers_tool(...)`. Add a task-level regression checking both output files.

### 2. [major] Population runs can finish successfully with NaN weights
- where: `loud/population.py:232`
- evidence: Training-loss checks inspect the loss computed before the optimizer step. Unlike `loud/train.py:143`, population training never checks final parameters for finiteness. I injected NaNs into the head immediately after the final optimizer step of a small CPU population run with `official_eval: false`. It saved a non-finite `final.pt` and returned `complete: True`, `heldout_loss: nan`. Official scoring catches this later when enabled, but scoring is an accepted optional setting.
- fix: Apply the shared loop’s finite-parameter guard before saving the final population model and recording completion. Add a final-step fault-injection regression.

### 3. [major] E6’s training clock includes diagnostics absent from its baseline
- where: `loud/h8.py:563`, `loud/h8.py:702`
- evidence: Every E6 config enables `compare_every: 1` and `rank_every: 10`. The comparison computes an additional complete block-local reference gradient, allocates flattened gradient vectors and synchronizes to obtain its cosine. Stable-rank logging performs a spectral-norm calculation per block matrix. Both execute inside `update()`, whose entire duration enters `train_seconds` at `loud/train.py:115–119`; the baseline leaves these diagnostics disabled. A tiny CPU reproduction increased synthesis time from 26 ms to 42 ms per call with comparison enabled. This is not a GPU timing estimate, but it confirms substantial diagnostic work contaminates the comparison.
- fix: Exclude synchronized diagnostic durations from the training clock, using the shared paused-diagnostic mechanism or equivalent explicit accounting.
